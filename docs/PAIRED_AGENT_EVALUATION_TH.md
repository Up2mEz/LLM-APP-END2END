# การเปรียบเทียบ agent รุ่นเก่ากับรุ่นปัจจุบันด้วยเงื่อนไขเดียวกัน

เอกสารนี้อธิบายรอบ `paired-agent-v30-current-20261105` ผลยังไม่ครบจนกว่าจะมีทั้ง `metrics.json`, `judge_metrics.json` และ `paired_summary.json` ในโฟลเดอร์รายงานของรอบนี้

## ผลการรันที่ตรวจยืนยันแล้ว

รันใหม่ครบ 120 คำตอบจาก 60 คู่คำถาม ใช้ proxy 361 ครั้ง ไม่รวมคำตอบจากแคชเก่า ตรวจรหัสไฟล์หลังรันผ่าน ผลที่ยืนยันได้ก่อนผู้ตรวจให้คะแนนมีดังนี้

| รายการ | รุ่นเก่าที่กู้จาก v30 | รุ่นปัจจุบัน |
| --- | --- | --- |
| จำนวนคำถาม | 60 | 60 |
| เลือกตอบหรืองดตอบตรงกับเฉลยและไม่ใช่บริการล้มเหลว | 57/60 | 57/60 |
| หลักฐานอ้างอิงหลักตรงกับเฉลยในข้อที่ตอบได้ | 38/51 | 38/51 |
| บริการล้มเหลว ซึ่งนับเป็นไม่ผ่าน | 1 | 2 |

ข้อความคำตอบตรงกัน 53 คู่ และสถานะตอบ/งดตอบ/ผิดพลาดตรงกัน 56 คู่ การเลือกตอบตรงประเภทและการมีหลักฐานตรงเฉลยยังไม่ยืนยันว่าเนื้อหาคำตอบถูกครบ จึงยังไม่มีข้อสรุปว่ารุ่นใดตอบถูกกว่ากันจนกว่าจะตรวจคำตอบเสร็จ

Luna สามงานแรกล้มเหลวเพราะโควตาผู้ให้บริการหมด ไม่มีไฟล์คำตัดสินจากงานเหล่านั้น การลองใหม่ตรวจเฉพาะคำตอบที่บันทึกไว้ ไม่เรียก Gemma ซ้ำ และไม่เปลี่ยนผลการรัน รายละเอียดที่คำนวณซ้ำได้อยู่ใน `reports/paired-agent-v30-current-20261105/execution_summary.json`

## เปรียบเทียบอะไร

กู้โค้ด agent ที่ใช้ในรุ่น v30 จากประวัติ Git และตรวจไฟล์ทั้ง 18 รายการกับรหัสตรวจสอบไฟล์ที่บันทึกไว้ เทียบกับโค้ดปัจจุบันโดยใช้คำถามเดิม 60 ข้อ ซึ่งประกอบด้วยชุดพัฒนาเดิม 30 ข้อและชุดพัฒนาเพิ่มเติม 30 ข้อ ทั้งสองชุดเคยใช้ปรับระบบแล้ว

ReAct ในที่นี้หมายถึงวงรอบที่โมเดลเรียกเครื่องมือ รับผล แล้วตัดสินใจทำขั้นต่อไป แอปมีเครื่องมือค้นเอกสารและเงื่อนไขหยุด ไม่ได้เปิดเผยความคิดภายในโมเดล และคำนี้คนละความหมายกับ React ที่ใช้ทำหน้าเว็บ

## ทำให้เทียบกันได้อย่างไร

| สิ่งที่ควบคุม | เหมือนกันทั้งสองรุ่น |
| --- | --- |
| คำถามและเอกสาร | คำถาม 60 ข้อเดียวกัน ข้อมูลเอกสารชุดเดียวกัน พร้อมรหัสตรวจสอบไฟล์ |
| โมเดลตอบ | gemma-4-E4B-it ผ่าน class proxy, temperature 0 |
| การค้น | การค้นแบบผสมและเปิดการจัดอันดับหลักฐานซ้ำ |
| แคช | ปิดการอ่านและเขียนแคชคำตอบและคะแนนจัดอันดับซ้ำ |
| งบแต่ละคำถาม | โมเดลไม่เกิน 6 รอบ ค้นไม่เกิน 3 ครั้ง เวลารวมไม่เกิน 150 วินาที |
| บริบทและคำตอบ | บริบท 18,000 ตัวอักษร หลักฐานไม่เกิน 20 ชิ้น คำตอบโมเดลไม่เกิน 1,400 tokens |
| ลำดับทดลอง | สลับรุ่นที่ตอบก่อนในแต่ละข้อ แล้วรันอีกรุ่นในคู่เดียวกันทันที |
| ผู้ตรวจ | GPT-6-Luna ที่ตั้ง reasoning effort เป็น xhigh ใช้เกณฑ์เดียวกันและไม่เห็นชื่อรุ่น |

เพื่อควบคุมแคชและการเชื่อมต่อ ทั้งสองรุ่นใช้ตัวเชื่อมต่อ proxy และตัวจัดอันดับที่รองรับการปิดแคชชุดเดียวกัน จึงเป็นการเทียบตรรกะ agent ภายใต้เงื่อนไขที่ปรับให้ตรงกัน ไม่ใช่การนำโปรแกรมเก่าทุกส่วนมารันโดยคงสภาพบริการในอดีต

รอบนี้เรียก `Agent.run` โดยตรงเหมือนกันทั้งสองรุ่น ไม่วัดเวลาหน้าเว็บหรือ HTTP เส้นทาง FastAPI ที่ใช้งานจริงมีหลักฐานจากการประเมิน Capstone รอบก่อน ส่วนการทดลองนี้มุ่งแยกคำถามเรื่อง agent เก่ากับใหม่

## นับผลอย่างไร

เก็บคำตอบใหม่ครบทั้งคู่ก่อนให้คะแนน ไม่ใช้คำตอบจากแคช v30 หรือเติมคำตอบจากรอบอื่น ผู้ตรวจอ่านคำถาม เฉลย หลักฐาน และคำตอบโดยเห็นเพียงเลขรายการที่สุ่มลำดับไว้

ผลสำเร็จรวมการตอบถูกครบและการงดตอบที่ถูกต้อง คำตอบผิด ไม่ครบ ไม่รองรับด้วยหลักฐาน งดตอบเกินจำเป็น และบริการล้มเหลวล้วนไม่ผ่าน หาก worker ค้างจะบันทึก timeout เป็นข้อผิดพลาด และนับจำนวนเรียก proxy เผื่อไว้ 12 ครั้งเพราะไม่สามารถทราบจำนวนจริงหลังถูกหยุด ไม่ยิงคำถามเดิมใหม่แทนผลที่เสีย

สรุปแบบจับคู่เป็นสี่กลุ่ม: ถูกทั้งคู่ ผิดทั้งคู่ รุ่นเก่าถูกฝ่ายเดียว และรุ่นปัจจุบันถูกฝ่ายเดียว พร้อมแสดงความต่างของอัตราสำเร็จ ช่วงความไม่แน่นอนจากการสุ่มคู่คำถามซ้ำ และการทดสอบจากคู่ที่ให้ผลต่างกัน ค่าสถิติเหล่านี้ไม่รวมความผิดพลาดของผู้ตรวจที่เป็นโมเดล

## ขอบเขตการสรุป

เลขรุ่นสูงกว่าไม่รับประกันคะแนนสูงกว่า แม้ temperature เป็นศูนย์ การเรียกบริการโมเดลคนละครั้งยังอาจให้คำตอบต่างกัน รอบนี้มีคำตอบหนึ่งครั้งต่อรุ่นต่อคำถาม จึงไม่ใช้แยกสาเหตุเล็กน้อยว่าเกิดจากโค้ดหรือความแปรผันของโมเดลโดยเด็ดขาด และไม่ใช้ยืนยันผลกับคำถามใหม่หรือความถูกต้องทางคลินิก

ผลการเทียบวิธีค้น dense กับ hybrid ในรอบ `capstone-current-v2` ตอบอีกคำถามหนึ่ง คือควรเลือกวิธีค้นแบบไหน ผลการเทียบ agent ในเอกสารนี้จึงแยกตารางและตัวหารจากผลดังกล่าว
