# อ่านระบบและผลทดลองอย่างไร

## ตอนนี้เลือกใช้อะไร

แอปใช้ Gemma รุ่น `gemma-4-E4B-it` ผ่านบริการกลางของรายวิชา ค้นเอกสารด้วยการค้นแบบผสมและเปิดการจัดอันดับหลักฐานซ้ำเป็นค่าเริ่มต้น หน้าเว็บใช้ React ส่วนเซิร์ฟเวอร์ใช้ FastAPI ผลสำหรับส่งงานคือการประเมินใหม่ชื่อ `capstone-current-v2` มีคำถาม 30 ข้อและเปรียบเทียบสองวิธีภายใต้ค่าตั้งเดียวกัน

## ทำไม v30 ได้คะแนนสูงกว่า ทั้งที่เก่ากว่า

ทดลองแบบจับคู่เสร็จแล้ว โดยกู้โค้ด v30 ที่ตรวจ hashes ได้และควบคุมคำถาม โมเดล งบเครื่องมือ แคช และผู้ตรวจให้เหมือนกัน รุ่นเก่าและรุ่นปัจจุบันได้ 56/60 เท่ากัน จึงยังไม่อ้างว่ารุ่นใหม่แม่นยำกว่า ดู [ผลเทียบรุ่นเก่ากับปัจจุบัน](PAIRED_AGENT_EVALUATION_TH.md) การทดลองนี้แยกจากการเทียบวิธีค้น dense กับ hybrid ซึ่งใช้ตอบว่าควรเลือกวิธีค้นแบบไหน

หลักฐานใน [ผลเปรียบเทียบเก่า](../reports/evaluations/v32/comparison.json) ระบุว่า v30 ใช้คำตอบจากแคช และมีการเรียก API ใหม่ 0 ครั้ง ส่วน v32 เรียกใหม่ 180 ครั้ง คะแนนรวมเปลี่ยนจาก 60/60 เป็น 57/60 บนคำถามเดิมที่เคยใช้พัฒนา ผลต่างนี้ไม่ได้แยกผลของโค้ดออกจากความแปรผันของคำตอบและบริการ จึงสรุปไม่ได้ว่า v30 เป็นระบบที่ดีกว่า

รอบปัจจุบันเปลี่ยนทั้งขอบเขตการทดลองและผู้ตรวจ: ใช้ dev 30 ข้อ ปิดแคช และให้ Luna ตรวจแบบไม่เห็นชื่อวิธี คะแนนจึงไม่ควรถูกจัดอันดับรวมกับตารางเก่า การเลือก hybrid อ้างจากการเปรียบเทียบภายในรอบปัจจุบัน: ความครอบคลุมหลักฐานห้าอันดับแรกเพิ่มจาก 0.82 เป็น 0.90 ส่วนคำตอบที่ผู้ตรวจให้ผ่าน รวมการงดตอบที่ถูกต้อง เพิ่มจาก 23 เป็น 28 ข้อจาก 30 ข้อ

## ยังตรงโจทย์หรือไม่

โค้ดครอบคลุมการตรวจรูปแบบคำตอบ การค้นพร้อมอ้างอิง การวัดผล การให้โมเดลเรียกเครื่องมือพร้อมเงื่อนไขหยุด และเว็บที่ใช้งานได้ รวม 5 กลุ่มความสามารถตามโจทย์ มีทั้งกลุ่มประเมินและกลุ่ม agentic ตามที่บังคับ ดู [หลักฐานตามข้อกำหนด](../reports/CAPSTONE_REQUIREMENTS_CHECK_TH.md)

ผลปัจจุบันแสดงการปรับปรุงเหนือวิธีตั้งต้น แต่ยังเป็นการประเมินบนชุดพัฒนาและใช้โมเดลตรวจคำตอบ ต้องเปิดเผยข้อจำกัดนี้ และการสาธิตรับคำถามใหม่ต่ออาจารย์ยังเป็นส่วนหนึ่งของการสอบ ไม่สามารถใช้คะแนนในรายงานแทนได้
